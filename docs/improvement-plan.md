# 持續改善與驗收

這份清單以目前程式、測試與部署證據為準。目標是讓作品在可靠性、安全、資料復原、效能、可用性與維護上都有可檢查的成果。免費方案與擁有者 Access 門禁是必要條件，不會為了完成清單開啟付費服務。

| 項目            | 完成條件                                                                                     | 目前狀態                                   |
| --------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 註冊與 API 恢復 | 帳號/session 同批回滾；錯誤保留狀態；登入過期保留草稿；跨帳號禁止重送                        | 已部署，測試與 CI 通過                     |
| 密鑰輪替        | 獨立 session key、版本化 pepper、舊帳號升級、競爭與回滾驗證、操作文件                        | 已部署，CI 與建置通過                      |
| 本機草稿        | 有期限、容量上限與 user/board 隔離；重新整理能恢復；切換帳號與登出清除；衝突由使用者決定     | 已部署，22 個 E2E 通過                     |
| 備份與還原      | 有版本與驗證的匯出；預覽/dry-run；新本機 D1 還原核對實體與關聯；寫入受授權與配額保護         | 待完成                                     |
| 用量與維護      | 擁有者可讀取容量；配額耗盡有可行處理；事件保留不破壞 UUID 去重、replay 與舊 cursor           | 容量頁面已實作；維護與事件保留待完成       |

| 正式站驗收      | 擁有者完成 Access 登入；觀察註冊/登入、導航、資料變更、雙瀏覽器重連與衝突                    | 待擁有者登入後驗證                         |
| 作品交付        | 中英 README、架構/操作文件、公開遊樂場、錄影與上述成果一致                                   | 已有基礎，隨變更更新                       |

每批程式變更先完成 lint、typecheck 與 runtime 測試，再分開提交；推送前執行完整 verify。影響協作或登入的變更另跑獨立瀏覽器情境。部署後檢查實際 Worker 版本、流量、門禁、CI 與建置紀錄。綠色 CI、Access 302 或展示錄影都不能替代正式站的登入後驗收。

舊對話提到的原始附件目前不在磁碟上；現有需求依 repository 的架構、安全、交付與審查文件核對。若取得原始設計文件，還需逐項比對，不能宣稱已驗收未讀到的條件。

大型看板的本機數據與測試重現方式見 [snapshot performance](snapshot-performance.md)。4,000 則留言的比對已改成線性掃描；整份快照的資料量與讀取成本仍需處理，不能把這項改善當作大型看板的完整驗收。
