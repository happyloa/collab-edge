# Interface languages

Supported locales: `en` (default) and `zh-TW` (Traditional Chinese). Every main screen exposes a keyboard-accessible language select with native language names.

The root layout reads the allowlisted `collabedge_locale` cookie and passes the locale into a client context. Server HTML and hydration begin with the same language. Changing the select updates the context, document `lang` and a one-year SameSite=Lax cookie (Secure on HTTPS). No reload, query invalidation or WebSocket reconnection is needed. Cookies store a display preference, not authorization. Unsupported cookie values fall back to English.

`src/i18n/messages.ts` contains English source keys and Traditional Chinese translations. Use `useI18n().t(key, values)` for interface text. Use full phrases with named placeholders for variable values; never translate user-authored names, descriptions, comments or filenames. Keep role option values and protocol identifiers unchanged. Dates use the selected locale; activity identifiers are translated only when displayed.

Errors remain canonical English in API responses and socket state. `errorText()` translates recognized messages at render time, allowing a displayed error to switch languages without another request. Unknown Chinese-mode errors use a safe general message. This is a presentation layer, not a protocol change. Browser-native validation/file-picker text follows browser settings. Cloudflare Access pages and managed OTP emails are not controlled by this context.

Regression coverage includes route navigation, reload persistence, initial Chinese HTML without JavaScript, invalid-cookie fallback, translated validation, retained drafts, unchanged user content, active sockets and a narrow viewport. Existing English collaboration tests continue to exercise the same endpoints and role values.

The implementation adds no i18n dependency, external translation service, database writes or Cloudflare paid feature.
