# Local draft recovery

Card details and unsent comments are saved in this browser's IndexedDB. The board lists saved drafts with a preview and timestamp. Choose **Review draft** to reopen one. Closing an edited dialog offers **Keep draft and close**, **Discard and close**, or **Continue editing**; Escape follows the same flow. Focus returns to the previous control, or the board heading if that control has disappeared.

The device keeps at most 24 records and 256 KiB of UTF-8 JSON, with a 96 KiB limit per record. A record expires seven days after its last edit. Form drafts and unconfirmed mutations share these limits. Expired, malformed and unsupported records are removed when storage is read. Full or unavailable storage shows a message and retains the current inputs; new mutations wait until their device copy is committed. A browser that blocks IndexedDB can still read boards but cannot submit board mutations through this UI.

Each dialog has its own record, so two tabs editing the same card do not overwrite each other's drafts. IndexedDB transactions check the active account generation, validate records and enforce limits together. Successful sign-in under another account clears the former account's device drafts. Successful explicit sign-out, password reset and account deletion clear them too. A stale tab cannot recreate the former generation. Session expiry alone keeps drafts available for recovery after signing back into the original account.

Restoring a form retains its original revision and the baseline for fields the author changed. Fields left untouched follow the current server snapshot. A restored description cannot overwrite a teammate's newer description without the existing conflict flow. Read-only and archived card drafts remain available to review and copy; server authorization still controls submissions.

Before sending a mutation, the client saves its original UUID, revision and command. An acknowledgement or committed event removes that device record. After a reload, uncertain writes appear for review and are not automatically sent. **Retry my draft** first uses the original UUID and revision, allowing server deduplication if the write already committed. A confirmed field conflict requires a separate explicit retry with a new UUID. Failed deletion keeps the visible mutation draft available.

This feature saves authored card content, comments and mutation commands. It does not save passwords, authentication tokens, cookies or attachment bytes. Browser storage is neither an encrypted vault nor a database backup. Clearing browser data removes the drafts. Wait for **Draft saved on this device** before closing the browser; the UI prompts before leaving when the latest edit has not finished saving. Recovery requires loading the board from the server, so a full page reload while offline is not supported.

Implementation: [transactional store](../src/drafts/store.ts), [field restoration](../src/drafts/restore.ts), [socket queue](../src/realtime/socket-client.ts) and [card dialog](../components/board/card-dialog.tsx). The [browser scenarios](../e2e/drafts.spec.ts) exercise offline editing followed by an online reload, independent tabs, conflict guards, original-UUID deduplication, shared count/byte limits, expiry, account switching, explicit sign-out and unavailable storage. No Cloudflare resource or API request is used to persist drafts.
